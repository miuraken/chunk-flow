# 端末内の音声認識エンジンのベンチマーク（2026-10-22、Pixel 8 Pro）

端末内の 8 つの音声認識エンジンを、10 言語について実機で測り、言語ごとに採用するエンジンを絞るための材料にまとめた。
計測の道具は [`tools/stt-bench/`](../../tools/stt-bench/README.md)（端末側は debug ビルドの `SttBenchActivity`）。

> [!IMPORTANT]
> 実際の教材の音声・切り出したクリップ・文字起こし（正解を含む）は著作物なのでコミットしていない（AGENTS.md §10）。
> この文書には集計の数値と、合成音声（自作の文）の例だけを載せる。

## 1. 結論: 言語ごとの採用候補（案）

役割は次の 4 つ。**標準** = 取り込みのときにまとめて文字起こしするエンジン、**高速** = 端末内で速く終わる代わり、
**高精度** = 1 チャンクずつの「より詳しく文字起こし」向け（遅い）、**予備** = ほかが使えないときの最後の手段。

| 言語 | 残す（案） | 外す（案）と理由 |
| --- | --- | --- |
| 英語 | ML Kit（標準）、Moonshine Base（高速）、Whisper Small（高精度）、Whisper Tiny（予備） | SpeechRecognizer（ML Kit と同じモデルで遅い）、Whisper Base・SenseVoice（Moonshine のほうが速くて同等以上）、Moonshine Tiny（Base との差が小さい。容量を優先するなら Base の代わりに） |
| 日本語 | ML Kit（標準）、SenseVoice（高速）、Whisper Small（高精度） | SpeechRecognizer、Whisper Base・Tiny（誤りが多い）、Moonshine Tiny・Base（漢字が仮名になる・文頭が欠ける。実教材で CER 約 20%） |
| 中国語（普通話） | SenseVoice（標準）、ML Kit（別解）、Whisper Small（高精度）、Moonshine Base（高速の別解） | SpeechRecognizer、Whisper Base・Tiny、Moonshine Tiny（配布元にファイルがなく入れられない） |
| 広東語 | SenseVoice（標準。広東語の書き言葉で出せる唯一のエンジン）、Whisper Small（予備。標準中国語の書き言葉になる） | Whisper Base・Tiny（ML Kit・SpeechRecognizer・Moonshine は非対応） |
| 韓国語 | ML Kit（標準）、SenseVoice（高速）、Moonshine Tiny（高速・69 MB）、Whisper Small（高精度） | SpeechRecognizer、Whisper Base・Tiny、Moonshine Base（不具合: 実教材の 4 割で "audiotext" とだけ出る） |
| ヒンディー語 | ML Kit（標準）、Whisper Small（端末内の ONNX で唯一使える。遅い） | SpeechRecognizer、Whisper Base・Tiny（ウルドゥー文字・ローマ字で出る。予備にも使わない） |
| スペイン語 | ML Kit（標準）、Moonshine（Tiny と Base は同じファイルなので 1 つにまとめる）、Whisper Small（高精度） | SpeechRecognizer、Whisper Base・Tiny |
| アラビア語 | Moonshine Tiny（標準・28 MB）、Moonshine Base（別解。母音記号つきで出る）、Whisper Small（高精度） | Whisper Base・Tiny（ML Kit・SpeechRecognizer は非対応） |
| ウクライナ語 | Moonshine Base（標準）、Whisper Small（別解） | Moonshine Tiny（容量が Base とほぼ同じで精度が低い）、Whisper Base・Tiny（ML Kit・SpeechRecognizer は非対応） |
| ベトナム語 | ML Kit（標準）、Moonshine Base（高速）、Whisper Small（別解） | SpeechRecognizer、Moonshine Tiny（容量が Base とほぼ同じで精度が低い）、Whisper Base・Tiny |

判断が必要なところ:

1. **SpeechRecognizer を一覧から外すか。** この端末では ML Kit と同じモデルとみられ、結果はほぼ同じで（違いは金額などの書式くらい）、
   遅い（§4.1）。一覧からは外し、ML Kit が使えないときの自動の予備としてだけ残す案。
2. **Whisper Tiny をどこまで残すか。** 言語判定のために同梱しているので容量は増えないが、精度はほぼ全言語で最下位。
   上の案では英語の予備にだけ残した。
3. **英語の Moonshine を Base と Tiny のどちらにするか。** 274 MB / 118 MB、実教材の WER 3.2% / 3.9%。
4. **中国語の Moonshine Base を残すか。** SenseVoice と同じくらい速いが、実教材では誤りが多い（6.1% と 1.8%）。SenseVoice を入れないときの代わり。
5. **Whisper Small をどう扱うか。** 多くの言語で上位だが、音声の 2〜4 倍の時間がかかり、メモリが約 1.3 GB 増える。
   取り込みのときの一括の文字起こしには向かないので、「より詳しく文字起こし」専用にする案。
6. スペイン語・アラビア語・ウクライナ語・ベトナム語は合成音声（12〜24 文）だけで決めている。実際の教材で確かめたい。

## 2. 測り方

- **端末**: Google Pixel 8 Pro（Tensor G3、Android 17、RAM 11 GB）。アプリは debug ビルド（0.1.0）。
- **経路**: 本番の「より詳しく文字起こし」と同じ経路（`transcribeChunkTrial`）で、学習言語だけを指定し、エンジンを 1 つに固定した
  （ほかのエンジンに切り替えない）。エンジンごとにアプリを起動し直し、言語ごとに先頭のクリップで 1 回ウォームアップしてから
  （これを「初回」として記録）、全クリップを 1 つずつ文字起こしした。各回の前に 10 秒休ませ、端末が熱いときは冷えるまで待った。
- **音源**
  - **実教材**: `sample_files/` の 9 本（語学教材）から無音で区切って切り出し、端末の言語判定（Whisper Tiny）で確信度 0.85 以上の
    クリップを残した。211 クリップのうち、言語が混ざるものなど 9 件を除いた 202 件を採点した
    （英語 36・日本語 34・中国語 30・広東語 35・韓国語 35・ヒンディー語 32）。1 クリップは 1.5〜4 秒ほどの短い発話。
  - **合成音声**: macOS の `say` で 10 言語 × 12 文（語学教材でよくある場面の文。数字は入れない）。英語・スペイン語は 2 人、
    ほかは 1 人の自然な声を主な結果にした。日本語・中国語・韓国語の 2 人目の声（Eddy）はロボット的な声なので、別に集計した（§3.2）。
- **正解**
  - 合成音声: 読ませた文そのもの。
  - 実教材: クラウドを使わず、8 つのエンジンの出力を突き合わせて正解を作った（信頼性は合成音声より下がる）。
    広東語は SenseVoice の出力を直したものに近く、SenseVoice に有利（広東語の SenseVoice の 0.0% は割り引いて見る）。
- **指標**
  - 精度: 日本語・中国語・広東語・韓国語は CER（文字誤り率）、ほかは WER（単語誤り率）。句読点・記号・大文字と小文字・
    数字の書き方（「2」と「二」など）・簡体字と繁体字の違いは誤りに数えない（[`score.py`](../../tools/stt-bench/score.py)）。
  - 速度: 1 クリップの処理時間の中央値、RTF（処理時間の合計 ÷ 音声の長さの合計。1 より小さければ音声より速い）、初回（モデルの読み込みを含む）。
  - メモリ: モデルを読み込んだことで増えたアプリのプロセスの PSS。
- **注意**
  - ML Kit と SpeechRecognizer の時間の大半は、アプリが音声を流す時間（本番と同じ速さ）で、推論の速さではない。
    この 2 つのモデルはシステムのプロセスで動くので、アプリのメモリには表れない。
  - 同じ条件で測り直しても、速度が 1.5 倍ほどぶれることがあった（Moonshine Tiny の英語の中央値が 195 ms と 288 ms）。
    1.5 倍以内の速度の差は、差がないものとして見る。

## 4. わかったこと

1. **ML Kit と SpeechRecognizer は、この端末では同じモデルとみられる。** 合成音声（自然な声）では全言語で誤り率が一致し、
   実教材でも 167 件中 157 件で一致した。違った 10 件は主に書式で、ML Kit は金額を「$」つきで書き、固有名詞の綴りも整えるが、
   SpeechRecognizer は数字だけを出す（英語では金額の単位が落ちて誤りになる）。
   SpeechRecognizer が 1 クリップあたり 0.8〜1.4 秒遅いのは、アプリ側の音声の流し方の違い（ML Kit は 20 ms 分を 4 ms ごと、
   SpeechRecognizer は 10 ms ごとに流し、試行のあいだに 200 ms 待つ）。ML Kit は基本モードで動いた（高度モードは Pixel 10 以降）。
   対応言語も同じ（en ja zh ko hi es vi。広東語・アラビア語・ウクライナ語は非対応）。
2. **SenseVoice は中国語・広東語で最良。** 日本語・韓国語でも ML Kit に次ぐ精度で、ML Kit の 5 倍ほど速い。
   ロボット的な声にも強い（§3.2）。英語は Moonshine に少し劣る。
3. **Moonshine は修正（§5.1）のあと、多くの言語で上位に入った。** 英語、中国語（Base）、韓国語（Tiny）、ベトナム語（Base）、
   ウクライナ語（Base）、アラビア語。日本語は漢字が仮名になる（「友達と山へ」→「ともだちとやまへ」）、文頭が欠ける
   （「おはようございます。今日はお元気ですか。」→「今日はお元気ですか。」）ことが多く、実教材で CER 約 20%。
   スペイン語は正確だが、ほかの言語の 5 倍遅い（§5.5）。
4. **Whisper.** Small は多くの言語で上位だが、遅くて重い。Base は、どの言語でもほかのエンジンのどれかに速さと精度の両方で負けた。
   Tiny はほとんどの言語で最下位。広東語は標準中国語の書き言葉、ヒンディー語は Base でウルドゥー文字・Tiny でローマ字になる。
5. **初回（モデルの読み込み）。** SenseVoice は日本語などで 0.3 秒、ML Kit は 1.3〜2 秒、Moonshine は 1〜4 秒、Whisper Small は 6〜11 秒。

## 5. 見つかった不具合と対応

### 5.1 Moonshine: 英語以外の出力が途中で切れる（修正済み）

デコードするトークン数の上限が、英語向けの「1 秒 6.5 トークン」のままだった。日本語・中国語・韓国語などは 1 文字が複数のトークンに
なるので文の途中で切れ、末尾に壊れた文字（U+FFFD）が出ていた。英語以外は、Moonshine の言語別モデルのモデルカードの値
（1 秒 13 トークン）にした（`MoonshineOnnxTranscriber.maxDecodeTokens`）。修正前後の誤り率:

| 言語 | エンジン | 実教材（修正前 → 後） | 合成音声（修正前 → 後） |
| --- | --- | ---: | ---: |
| 日本語 | Tiny | 33.1% → 20.5% | 10.9% → 7.7% |
| 日本語 | Base | 29.1% → 20.9% | 14.5% → 10.0% |
| 中国語 | Base | 11.4% → 6.1% | 5.8% → 1.4% |
| 韓国語 | Tiny | 35.0% → 1.2% | 42.8% → 4.3% |
| 韓国語 | Base | 76.5% → 55.0% | 45.5% → 5.9% |
| アラビア語 | Tiny | — | 31.6% → 14.5% |
| アラビア語 | Base | — | 48.7% → 15.8% |
| ベトナム語 | Tiny | — | 33.6% → 5.2% |
| ベトナム語 | Base | — | 31.9% → 0.9% |

英語・スペイン語・ウクライナ語は変わらなかった（切れていなかった）。

### 5.2 SpeechRecognizer・ML Kit: 読み手が音声を読まないと文字起こし全体が止まる（修正済み）

計測の準備中に一度、SpeechRecognizer が音声を読み始めないまま、アプリの書き込みのスレッドがパイプへの `write` で止まった
（スレッドダンプで確認）。止まった `write` はキャンセルでもタイムアウトでも抜けられず、認識のロックを持ったまま文字起こし全体が止まる。
書く前に `poll`（POLLOUT）で書けることを確かめ、3 秒読まれなければ流すのをやめるようにした（`PipeWriteGuard`。ML Kit の経路も同じ）。

- 通常のときの動作が変わらないことは実機で確かめた（修正の前後で出力が完全に一致し、速さも同じ）。
- **止まる条件は未確認。** 画面ロック中・アプリが背後に回ったときは、どちらも止まらず普通に動いた。当時は音声の言語パックを
  取得した直後だったので、それが関係している可能性がある。止まる経路そのものは実機で再現できていない（単体テストで確認）。

### 5.3 Moonshine Tiny のウクライナ語・ベトナム語が取得できない（修正済み、a5b827c）

デコーダの大きさと SHA-256 が配布元と違っていた。配布元に合わせた。

### 5.4 Moonshine Tiny の中国語が入れられない（未対応）

定義しているファイルが配布元にない（HTTP 404）。配布元には KV キャッシュを使わないデコーダしかなく、対応するにはそのための
デコードの処理を足す必要がある。中国語は Base と SenseVoice があるので、Tiny は一覧から外す案。

### 5.5 Moonshine Base の韓国語が "audiotext" とだけ出す（未対応）

実教材の 35 件中 15 件、合成音声の 24 件中 5 件で、本文の代わりに "audiotext" とだけ出た（Tiny では 0 件）。
Base の韓国語は、`tokens.txt` を Tiny の韓国語の配布元から取っていて、組み合わせが合っていない可能性がある（未確認）。

### 5.6 Moonshine のスペイン語が遅い（未調査）

精度は高い（WER 1.0%）が、RTF が 0.7 で、ほかの言語（0.1〜0.2）の 5 倍遅く、読み込みでメモリが約 470 MB 増える。
1 トークンあたりの時間がほかの言語の約 6 倍かかっている。Tiny と Base が同じファイル（`.ort` 形式）を使っている。原因は未調査。
