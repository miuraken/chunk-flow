## 4. アーキテクチャ・セキュリティ詳細監査

### 4.1 チャンク手動編集のトランザクション整合性と文字起こし引き継ぎ（§6.4, §7.4.6）
- `splitChunk` / `mergeWithNextChunk` / `moveChunkBoundary` はすべて `ChunkDao.replaceChunksTransaction`（`@Transaction`）を呼び出し、「新しい `MANUAL` チャンクの挿入 → 文字起こしの付け替え → 古い `MANUAL` チャンクの削除」を 1 トランザクションで実行している。
- `AUTO` または `IMPORTED` チャンクを表示中に初めて手動編集を行った場合も、元の `AUTO` / `IMPORTED` チャンクと文字起こしを破壊せず残したまま `MANUAL` チャンク群を生成し、`item_state.chunk_source` を `MANUAL` に切り替えるため、いつでも元のチャンク種別へ戻すことができる。
- 手動修正されたテキストや分割・結合結果は即座に `filesDir/media/<MediaId>.transcript.chunkflow.json` にアトミック書き込み（`.tmp` + `fd.sync()` + `renameTo`）で保存される。

### 4.2 再生位置とカラオケ強調の再コンポーズ隔離（§6.2, §7.5.5）
- `PlayerUiState` にはミリ秒単位の再生位置を含めず、`PositionProvider` を `WaveformSection`・`PlayerProgressSection`・`TranscriptList` に渡している。
- `TranscriptList` の単語ハイライト（F7.7）は `TranscriptChunkRow` 内で `isActive && !isMasked && wordRanges != null` の行のみが `LaunchedEffect` + `withFrameNanos` を起動し、発話中の単語インデックス範囲（`WordCharRange`）が変化したときのみ該当行の `activeWordRange` State を更新する。非アクティブ行や親の `TranscriptList` / `PlayerScreen` は一切再コンポーズされない。

### 4.3 バックアップ規則と入力制限（§8.1, §8.2）
- `app/src/main/res/xml/data_extraction_rules.xml` は `cloud-backup` と `device-transfer` の双方で `database`（`.`）と `file`（`datastore/`）のみを `include` しており、`filesDir/media/`（音声・文字起こし原本）および `filesDir/analysis/`（波形・特徴量キャッシュ）がクラウドバックアップや端末移行に含まれないことを `DataExtractionRulesTest` で保証している。
- 手動テキスト編集時は NFC 正規化と最大 2,000 コードポイント制限（`MAX_TRANSCRIPT_TEXT_CODE_POINTS`）、ブックマークのメモには NFC 正規化と最大 500 コードポイント制限（`MAX_BOOKMARK_NOTE_CODE_POINTS`）を適用している。
- 字幕・テキスト書き出し（`writeExportedTranscriptToUri`）では `targetUri.scheme == ContentResolver.SCHEME_CONTENT` を検証し、`file://` 等の不正スキームへの書き込みを拒否している。
