# 0008. 時間軸の対応（文字起こしの時刻の補正の初期値、シーク後の一定の誤差）

- 状態: 承認済み
- 日付: 2026-10-14
- 決めた人: lead（スパイク S2・S3 の結果をもとに）
- 根拠: [S3-audio-analysis.md](../spikes/S3-audio-analysis.md) §4.1〜4.2、[S2-playback.md](../spikes/S2-playback.md) §3（いずれもエミュレータ。デコーダは `c2.android.*`）
- 関係する節: 設計書 §7.4.3（形式の時刻の規則）、§7.4.6（時刻のずれの補正、F7.6）、§3（時刻精度）

## 背景

時刻の基準は 3 つある。真の時刻 T（元の PCM の位置）に対して:

- **PC ツール（ffmpeg 8 系）**: LAME / Xing ヘッダのある MP3 は T。ヘッダのない MP3 は T + 1,105 サンプル（ffmpeg はエンコーダ遅延 576 + デコーダ遅延 529 を削れない）。MP3 以外は T（ADTS は両者とも +23.2ms）。
- **ExoPlayer（既定）**: ヘッダのある MP3 は T − 529 サンプル（Media3 は 1,105 を削るが、`c2.android.mp3.decoder` はデコーダ遅延 529 を出力しないため削りすぎ。S3 の解釈）。ヘッダのない MP3 は T + 576。MP3 以外は ffmpeg と同じ。
- **ExoPlayer（ADR 0006 のヘッダを隠す DataSource）**: ヘッダのあった MP3 は T +（ヘッダのフレーム 1 つ分のサンプル数 + エンコーダ遅延）。ヘッダのフレームが無音として再生され、ギャップレスの情報も使われない（エンコーダ遅延とパディングを削らない）。1 フレームのサンプル数は MPEG-1（32 / 44.1 / 48kHz）で 1,152、MPEG-2 / 2.5（24kHz 以下）で 576。LAME の標準のエンコーダ遅延 576 では、MPEG-1 で T + 1,728（44.1kHz で +39.18ms）、MPEG-2 / 2.5 で T + 1,152（22.05kHz で +52.24ms）。ヘッダのない MP3 は T + 576（変わらない）。**S3 の D6 で同じ音源を直接測って確認した**（エミュレータ、`c2.android.mp3.decoder`）。

形式 v1（§7.4.3）は「エンコーダ遅延はギャップレス情報に従って取り除く（ffmpeg と ExoPlayer の既定の扱いに合わせる）」としていたが、
**MP3 では ffmpeg と ExoPlayer の扱いが一致しない**（S3）。

## 決定

1. **形式 v1 の時刻は「ffmpeg（PC ツール）でデコードした時刻」のままとする**（PC ツールは補正しない）。§7.4.3 の記述を事実に合わせて直す。
   アプリが取り込み時に、再生の時間軸との差を `transcriptOffsetMs` で吸収する。
2. **取り込み時の `transcriptOffsetMs` の初期値**（ExoPlayer の時刻 − ffmpeg の時刻。サンプルレート `sr` の ms に丸める）:

   | 音声 | 初期値 | 例 |
   | --- | --- | --- |
   | MP3（先頭フレームに Xing / Info / VBRI ヘッダあり。ADR 0006 で隠して再生） | **+(1 フレームのサンプル数 + エンコーダ遅延) / sr** | MPEG-1（32〜48kHz）・LAME: +1,728 / sr（44.1kHz で +39ms）。MPEG-2 / 2.5（24kHz 以下）・LAME: +1,152 / sr（22.05kHz で +52ms） |
   | MP3（ヘッダなし） | **−529 / sr** | 44.1kHz で −12ms、22.05kHz で −24ms |
   | MP3 以外 | 0 | 0 |

   - 1 フレームのサンプル数は MPEG のバージョン（ヘッダのフレームのヘッダ）から、エンコーダ遅延は LAME ヘッダ（LAME タグ）に書かれた値から求める。
     LAME タグがない（Xing / VBRI だけの）場合は、LAME の標準の 576 を仮に使う。LAME 以外のエンコーダの MP3 での値は**未確認**（エンコーダ遅延の値が正しく書かれていれば式で計算できる見込み）。
   - ヘッダの有無・MPEG のバージョン・エンコーダ遅延は、ADR 0006 の DataSource が隠すときに読める（解析の結果として DB に持つ）。
   - その後、F7.6 の自動補正（端末内の解析の立ち上がりとの比較、±500ms）で詰める。初期値は自動補正の探索の中心にも使う。
   - 補正の値はデコーダの実装に依存する（`c2.android.*` で計測）。**実機のデコーダで同じかを確かめ、違えば表を直す**。
3. **形式ごとのシーク後の一定の誤差は、当面補正しない。**
   - MP3 は ADR 0006 で先頭から再生したときとシーク後が同じ値になり、解析も同じ DataSource で読むので（ADR 0005）、チャンクの境界と再生の時間軸はずれない見込み。
   - AAC（m4a）はシーク後だけ +23.2ms（先頭からは 0）。誤差は正（チャンクの頭出しで、少し前の音から鳴る方向）で、前のパディング（`prePaddingMs` 150ms）に収まる。
   - 実機で再計測し、問題があれば形式ごとの固定値で補正する。

## D6 の結果（2026-10-14 追記）

S3 の D6（[S3-audio-analysis.md](../spikes/S3-audio-analysis.md) の D6 節）で、同じ音源を ffmpeg・ExoPlayer（既定 / 隠す）・`MediaExtractorCompat`（既定 / 隠す）で直接測った。

| 音声 | ExoPlayer（隠す）− ffmpeg（実測） | 当初の推定 |
| --- | --- | --- |
| ヘッダあり・44.1kHz（MPEG-1。CBR / VBR） | +1,728 サンプル（+39.18ms） | +1,728（合っていた） |
| ヘッダあり・22.05kHz（MPEG-2） | **+1,152 サンプル（+52.24ms）** | +1,728（**違っていた**。1 フレームが 576 サンプルのため） |
| ヘッダなし・44.1kHz / 22.05kHz | −529 サンプル | −529（合っていた） |

- ヘッダを隠した `MediaExtractorCompat` と、同じ DataSource の ExoPlayer の時刻は全ファイルで一致した（差 0。30 分の VBR でもドリフトなし）。
- 上の「決定 2」の表は、この結果に合わせて直した。

## 依頼者の推奨との違い（指摘。経緯）

依頼者の推奨は「MP3 の初期値を一律に −529 / sr」だったが、これは **ExoPlayer の既定（ヘッダを隠さない）での値**で、ヘッダのない MP3 にだけ当てはまる。
ADR 0006 を採ると、ヘッダのあった MP3 は再生の時間軸が +1,728 サンプルになるため、初期値は +1,728 / sr になる（44.1kHz で 51ms の違い。22.05kHz では 102ms で、§3 の目標 50ms を超える）。
この値は当初、S2（+39.2ms、ヘッダを隠した再生）と S3（ffmpeg の時刻）の計測を組み合わせて求めたものだった。その後 D6 で直接測り、MPEG-1 では合っていたが、MPEG-2 / 2.5 では +1,152 だった（上の「D6 の結果」）。
