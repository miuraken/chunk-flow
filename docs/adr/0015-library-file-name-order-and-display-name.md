# ADR 0015: ライブラリのファイルの並びをファイル名の昇順に固定し、元のファイル名を保存する

- 状態: 採用（2026-10-23）
- 関連: ADR 0013（タグとフォルダの色）、ADR 0014（フォルダの設定パネル）、設計書 §6.4、§7.5.2 D

## 1. 背景

人間からの指示（2026-10-22〜23）:

- ライブラリのファイルタブでは、ファイル名順（昇順）を常に採用し、並べ替えのメニューをなくす。
- 「名称順（昇順）」にしても、ファイル名順にならないことがあった。かならずファイル名順に並べる。
- 横スクロールできるタグの欄を、「言語」のチップのすぐ右に並べる（参考画像 `library_v2.2.png`）。

調べてわかったこと（人間の Pixel 11 のライブラリ、398 件）:

1. これまでの「名称順」は、まず手で並べ替えた順（`item_state.file_sort_order`）を比べていた。398 件中 393 件に値が入っていて、ファイル名の順と違っていた。
2. 次に比べていた `media_item.title` は、音声のタグのタイトル（なければ `DISPLAY_NAME` から作った名前）で、ファイル名ではない。360 件でファイル名と違う書き方だった（例: タイトル「ピンズラー 韓国語 01」、ファイル名「ピンズラー韓国語01.mp3」）。
3. ローカルのストレージから取り込んだ 280 件は、`local_file_path` や SAF のドキュメント ID（`primary:Music/…/01.mp3`）からファイル名がわかる。Google ドライブから取り込んだ 118 件は、ドキュメント ID（`acc=1;doc=encoded=…`）にファイル名を含まず、データベースにも元のファイル名を持っていないので、ファイル名順に並べられない。

## 2. 決定

1. **並びはファイル名の昇順だけにする。** ライブラリにファイルを並べる場所（フォルダの中、検索結果、タグや言語での絞り込み、ブックマークのタブなど）と、プレイヤーの「次のファイル」は、すべて `core:model` の `AudioItemFileOrder` で並べる。
   - 比べ方: ファイル名（拡張子を除く）→ タイトル → 教材 ID。名前は自然順（数字の並びを数値として比べ、大文字小文字を区別しない。`compareFileNamesAscending`）。
   - ファイル名は、`AudioItem.displayName`（元のファイル名）→ `localFilePath` の最後の名前 → `sourceUri` から取り出した名前（ローカルのストレージのドキュメント URI、`raw:`、`file://`）→ タイトル の順に使う（`AudioItem.sortableFileName()`）。
   - 並びの決め方は `core:model` に 1 つだけ置き、feature で複製しない。
2. **並べ替えのメニューと、ファイル行のドラッグでの並べ替えをやめる。** プレイリストの曲順とルートのフォルダの並べ替えは残す。
3. **元のファイル名を保存する。** データベースを v10 に上げ、`media_item` に `display_name TEXT`（NULL 可）を足す（`MIGRATION_9_10`）。`AudioItem.displayName` で受け渡す。
   - 取り込み・再スキャンのときに SAF の `DISPLAY_NAME` を保存する（playback の担当）。
   - v9 以前に取り込んだ教材（`display_name` が NULL）は、取り込みの処理が再生を妨げない形で `DISPLAY_NAME` を問い合わせて補う（`MediaItemDao.getItemsMissingDisplayName` / `updateDisplayName`）。
   - 取り込むファイル名は信頼できない入力として扱い、長さを制限し、制御文字を除く（§8.1）。表示と並びのためだけに使い、ファイルパスには使わない。
4. **ファイルタブの上部は 1 行にする。** 学習言語の絞り込みのチップ（`言語: すべて` など）と、その右に 🏷 のアイコンと横スクロールのタグのチップ（残りの幅）を並べる。
5. `item_state.file_sort_order` と、手で並べ替えた順を保存する処理（`reorderAllFiles`）は使わなくなる。列を消すにはテーブルの作り直しが要るので、今回は残し、ほかのスキーマ変更とまとめて消す。

## 3. 影響

- 前に選んでいた並べ替えの種類と、手で並べ替えた順は無視される。
- 元のファイル名を補うまでのあいだ、Google ドライブのファイルはタイトルで並ぶ（ファイル名と同じ並べ方で比べる）。
- `AudioItem` に引数（既定値 `null`）が増える。既存の呼び出しはそのまま動く。

## 4. 検討した別の案

- **タイトルで並べる**: タイトルは音声のタグから取るので、ファイル名と書き方が違う。不採用。
- **表示のたびに `ContentResolver` でファイル名を問い合わせる**: 一覧を出すたびに I/O が要り、Google ドライブではネットワークに出ることがある。再生を最優先する原則（§0）に反するので不採用。
- **`title` を元のファイル名で上書きする**: タイトルの表示が変わってしまう（人間はタグのタイトルを見慣れている）。不採用。
