# 0012. Material Design 3（Expressive）への UI 移行の方針

- 状態: 承認済み
- 日付: 2026-10-20
- 決めた人: 人間（判断）、lead（記録）
- 根拠: [docs/ux/m3-compliance-review.md](../ux/m3-compliance-review.md)（調査）、[docs/ux/m3-migration-plan.md](../ux/m3-migration-plan.md)（計画）
- 関係する節: 設計書 §7.5（画面仕様）、§10（開発プロセス）、`AGENTS.md` §3

## 背景

Chunk Flow の UI は Material 3 の上に載っているが、画面構造（上部タブ、操作の多い行）、部品の用途（Chip を再生操作に使用、自作チップ、長押し依存）、テーマ（Typography / Shapes 未定義、ハードコード色、言語パレットの未調和）、モーションの不足で、M3 のデザインランゲージから外れている箇所が多い（調査の §3）。
全面的な見直しは工数が大きく、見た目と操作が大きく変わるため、評価用のビルドで人間が使ってから採否を判断する。

## 決定

1. **ライブラリは下部ナビゲーション（Navigation bar / rail）に移行する。**
   - 4 セクション（フォルダ / ファイル / 再生リスト / ブックマーク）を `NavigationSuiteScaffold` の行き先にする。
   - **最下部の「直近に開いたファイルの概要と再生ボタン」のペーン（ミニプレイヤー）は残す**。Navigation bar の直上に置く。
   - フォルダタブ下部の「最近開いたファイル」セクションは、再生リストタブから同じ内容に到達できるため**廃止してよい**。
   - ブックマークタブ専用の再生コントローラーは、ミニプレイヤーの展開状態に統合する（詳細は計画書 §3.3）。
2. **言語役割のカラー（母語 / 学習言語）はダイナミックカラーに調和させる。** ただしアプリ全体の統一感を優先し、母語と学習言語が見分けられる色相差を保つ（計画書 §3.4）。
3. **M3 Expressive の API を積極的に採用する**（`ButtonGroup`、`ToggleButton`、`SplitButton`、`FloatingToolbar`、`LoadingIndicator`、`MotionScheme` など）。端末や OS の版に依存する要素（ダイナミックカラー以外）は増やさない。Experimental API の使用箇所は `core:designsystem` のラッパーに閉じ込める。
4. **書体は既定のまま**（同梱しない）。`Typography` は M3 既定の書体で 15 スタイル（+ Expressive の Emphasized）を定義する。
5. **評価用 APK は現在のアプリを上書きする**（applicationId は変えない）。そのため移行ブランチでは **Room のスキーマと DataStore のキーを変更しない**。
6. **作業は `main` と明確に分けたブランチ `m3-refresh`（統合ブランチ）で行う。** `main` への統合は、人間が評価して採用を決めた後に lead が行う。
7. ブランチを切る前に、`main` 上で**振る舞いを変えないリファクタリング**（巨大な画面ファイルの分割、重複する再生操作 UI の共通化）を行う。分割後の構成が、並列開発の担当境界になる。
8. 担当を見直す: `core/designsystem/` を ui から分け、新設の **`designsystem` エージェント**が持つ（テーマのトークン、共通部品、Expressive のラッパー、言語色の調和）。ui は `feature/` の画面に専念し、画面ごとに並列で動かす。

## 影響

- `AGENTS.md` §3 の表と `_agents/agents/designsystem.md` を追加・更新する（この ADR と同時）。
- 設計書 §7.5 は、移行ブランチ上で M3 版に書き換える（計画書 §4 の順序）。`main` の設計書は採用が決まるまで変えない。
- 見た目が変わるスクリーンショットの基準画像は、フェーズごとに人間の承認を得て更新する（ADR 0002、`AGENTS.md` §9）。
- 不採用になった場合は `m3-refresh` を破棄し、リファクタリング（決定 7）だけが `main` に残る。
