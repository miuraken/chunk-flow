# ADR-0011: 文字起こしエンジンの選び方（ML Kit を既定にする）と、言語設定・言語ごと・ファイルごとの上書き

- **状態**: 承認済み（人間の承認: 2026-10-17）
- **日付**: 2026-10-17
- **担当**: lead
- **関連**: 設計書 §6.1、§6.4、§7.5、F9.1、ADR-0010（「エンジンの選び方」の部分をこの ADR で置き換える）

---

## 1. 背景

- これまでの端末内の文字起こしは、アプリ全体で 1 つのエンジンを選ぶ設定でした。
  - 選択肢は「自動」「SpeechRecognizer だけ」「sherpa-onnx」「ML Kit」の 4 つで、既定は「自動」（SpeechRecognizer を優先し、sherpa-onnx で補う）です。
- 設定画面の「文字起こし設定」は、カタログの全言語（121 言語）のモデルの状態を並べていたため、項目が多すぎました。
- ML Kit の音声認識は性能がよく、対応する端末も多いので、使える端末・言語では ML Kit を既定にしたい、というのが人間の判断です。
- 教材ごとに、学習言語とベース言語で別のエンジンを使いたい場面があります。

## 2. 決定

### 2.1 言語設定（全体の設定画面に「言語設定」タブを新設）

- 対象言語・ベース言語の選択肢と、文字起こし設定に出る言語を、ここで選びます。
- 保存先は DataStore の新しいキー `language_settings_enabled_languages` です。
  - これまでのキー `enabled_languages` は読みません。前の選択は引き継がず、新しい既定から始めます（人間の判断）。
- 既定で有効にする言語は、端末の設定言語（複数あればすべて）と英語です。
- 一覧の並べ方：
  - 上に次の 13 言語を言語コード順に固定します：`ar`、`de`、`en`、`es`、`fr`、`hi`、`it`、`ja`、`ko`、`pt`、`ru`、`zh-cn`、`zh-tw`。
  - その下に、カタログ上でどれかのエンジン（ML Kit・SpeechRecognizer・sherpa-onnx の Whisper）が対応している言語を、言語コード順に並べます。
- 中国語：簡体中国語は `zh-cn`、繁体中国語は `zh-tw` を使います。
  - 区別のない `zh` は一覧に出さず、設定の上では `zh-cn` として扱います。
  - 今ある `zh` の教材は、簡体中国語として扱います。

### 2.2 エンジンの選び方

- エンジンは `SttEngine` で表します：`ML_KIT`、`SPEECH_RECOGNIZER`、`SHERPA_ONNX`。
- 自動のときに試す順番：ML Kit → SpeechRecognizer → sherpa-onnx（モデルがあるときだけ）。
  - ML Kit の基本モードと高度モードは、端末と言語に合わせて自動で選びます（高度 → 基本）。
- 優先するエンジンは、次の順に決めます。
  1. ファイルごとの上書き（学習言語用・ベース言語用）
  2. 言語ごとの設定
  3. 自動
- 指定したエンジンが使えないときは、止めずに自動の順番の残りに切り替え、そのことを表示します（`SttEngine.tryOrder`）。
- 言語ごとの設定は、DataStore の新しいキー `stt_engine_by_language` に保存します。
  - これまでのキー `transcription_engine` は引き継ぎません。ただし、2.5 の移行が終わるまでは `core:media` が使い続けます。

### 2.3 ファイルごとの上書き

- Room に表 `item_stt_override` を足します。
  - 列：`media_id`（主キー。`media_item` への外部キーで、教材を消すと一緒に消える）、`target_engine`、`base_engine`。エンジンの列が `NULL` なら、言語の設定に従います。
- スキーマを 3 から 4 に上げ、表を作るマイグレーションと、`MigrationTestHelper` のテストを書きます。
- 消した教材に書き込んで外部キー違反にならないよう、教材があるかの確認と書き込みを 1 つのトランザクションで行います。

### 2.4 モデルの管理

- アプリから削除できるのは、sherpa-onnx のモデルだけです。
- OS（SpeechRecognizer）と ML Kit のモデルは OS が管理するので、アプリからは取得の要求だけにします（削除は OS の設定から）。

### 2.5 移行の段取り

- 一度に切り替えず、次の段階で進めます。
  1. 新しい型と保存先を足す（lead）。
  2. `core:media` のエンジンの選び方を、新しい設定に切り替える（audio-analysis）。
  3. 設定画面に「言語設定」タブを足し、「文字起こし設定」をアコーディオンにする（ui）。
  4. ファイル設定シートに、ファイルごとの上書きを足す（ui）。
- 古い `OnDeviceTranscriptionEngine` と `UserSettings.transcriptionEngine` は、段階 2・3 で使う場所がなくなってから消します。
- 新しいキーと新しい表を使うので、アプリのデータを消す必要はありません。

## 3. 影響とトレードオフ

- ML Kit の音声認識はアルファ版で、互換性のない変更が入る可能性があります。
- ML Kit の音声認識には、音声を実時間の速さで渡す必要があります。そのため、1 レッスン分をまとめて先に文字起こしすると、レッスンの長さと同じくらいの時間がかかります。
- ML Kit の高度モードは Gemini Nano（AICore）を使うので、アプリが一番手前にないと動かない可能性があります（未確認。段階 2 で確かめる）。
- 言語設定の一覧は、Whisper の対応言語が多いので、ほぼ 100 言語になります。絞り込み検索で探す前提です。
- ML Kit は、利用状況の統計（本文ではない）を Google に送ることがあります。依存にも、そのための送信の部品が入っています。実際に送っているかは、スパイク S4 で確かめます。
- ADR-0010 のうち「エンジンの選び方（自動 = SpeechRecognizer 優先）」はこの ADR で置き換えます。それ以外（Whisper Tiny による 2 言語判定、優先キューなど）は ADR-0010 のままです。
